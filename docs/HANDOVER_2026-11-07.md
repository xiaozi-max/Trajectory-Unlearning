按你的要求，本机已后台启动一个**排队脚本**（即使一直等待也算「已启动」）：

- PID 文件：`work/logs/wait_pipeline.pid`（本机启动时 PID=1388563，可用 `ps -p "$(cat work/logs/wait_pipeline.pid)"` 复查）
- 启动命令：
  ```bash
  nohup bash scripts/experiments/wait_and_run_pipeline.sh \
    > work/logs/wait_and_run_pipeline.log 2>&1 &
  echo $! > work/logs/wait_pipeline.pid
  ```

行为：
1. 用与 `grab_gpus` 相同的阈值轮询 GPU（`GPU_COUNT` 张、每卡 free ≥ `GPU_MIN_MEMORY_MB`、util ≤ `GPU_MAX_UTIL`），**不抢卡、不 kill 别人的进程**；本机 0–3 号卡当前 100% util，所以它会一直等。
2. 卡齐后先 `curl /openapi.json` 检查 Gateway。
3. 依次跑 `collect_forget_pool.sh` → `score_jev.py --attempts --steps` → `run_mt_online.sh jev_girpo`。
4. 内置保护：forget pool 为空、或 JEV 判定 0 条危险 attempt 时**停在训练之前**并写日志，不会拿空池训练。

**你在另一台机器开跑之前，建议把这个本机排队任务停掉**，避免两边同时打同一个 ECS Gateway / JEV key：
```bash
touch work/STOP_PIPELINE          # 在下一个阶段边界优雅退出
# 或 kill "$(cat work/logs/wait_pipeline.pid)"
```

## 8. 关键陷阱速查

| 现象 | 原因 / 处理 |
|---|---|
| vLLM 报 `Free memory ... desired GPU memory utilization` | 别的作业占显存；`gpu_memory_utilization` 是**按整卡容量**预分配，加卡数不降低单卡需求。等独占卡，别强行 kill 别人进程 |
| `grab_gpus` 一直等 | `GPU_MAX_UTIL=10` + 共享卡 100% util；独占卡上是正常的立即通过 |
| collect 后 `no dangerous (harmful COMPLETE) trajectories found` | 设计好的保护：REJECT/FAILED 不会进 forget pool。4B 当前早停，需要先解决「模型不完成任务」 |
| 4B 从 step1 起输出散文 / INVALID action | `ACTION_HELP` 丢失。已修复 `gateway.py` 的 re-injection；ECS 必须同步最新版 `gateway.py` 并重启 |
| `/reset` 400 `'TaskPlan' object has no attribute 'initial_observation'` | 旧版缩进 bug 的 `gateway.py`；用本次提交的版本覆盖 ECS 后重启 |
| JEV 403 / URL 404 | `JEV_BASE_URL` 只能是 `https://api.typesafe.ai`，客户端自己加 `/v1/systemone` |
| benign 任务永远不 COMPLETE | 单轮 benign 没有 `success_patterns`，要走 `utils/evaluator.py`；已实现 |
| `lora_adapter/adapter_model.safetensors` 16 bytes | 导出坏了，权重在 FSDP shard 里；评测前必须 merge/导出 |
| push 后新机器缺数据 / 缺 `.env` | `work/`、`.env`、`sources/`、`agent_config.toml` 都被 gitignore，必须按 §6 重建 |
